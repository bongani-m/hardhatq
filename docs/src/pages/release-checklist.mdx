# Release Checklist

## Pre-Release

### Code Quality
- [ ] All tests pass: `go test -race ./...`
- [ ] `gofmt -l .` produces no output
- [ ] `go vet ./...` passes
- [ ] Benchmarks show no regressions
- [ ] No critical bugs in issue tracker

### Documentation
- [ ] Update CHANGELOG.md
- [ ] Update README.md if features changed
- [ ] Check all documentation links work

### Testing
- [ ] Run full test suite with race detector
- [ ] Test with real AMQP clients (Python, Go, Node.js)
- [ ] Test authentication and TLS
- [ ] Test crash recovery scenarios

## Release

1. Update CHANGELOG.md with release date
2. Commit final changes:
   ```bash
   git add CHANGELOG.md
   git commit -m "chore: prepare for v0.1.0 release"
   git push origin main
   ```

3. Create and push tag:
   ```bash
   git tag -a v0.1.0 -m "Release v0.1.0"
   git push origin v0.1.0
   ```

4. Wait for GitHub Actions to attach the four executables and publish `ghcr.io/bongani-m/hardhatq:v0.1.0`

5. Verify:
   ```bash
   wget https://github.com/bongani-m/hardhatq/releases/download/v0.1.0/hardhatq-linux-amd64
   chmod +x hardhatq-linux-amd64
   ./hardhatq-linux-amd64 --version
   ```

## Post-Release

- [ ] Monitor issue tracker for release-related bugs
- [ ] Create new CHANGELOG section for next version

## Hotfix

```bash
git checkout -b hotfix/0.1.1 v0.1.0
# make fix
git commit -m "fix: critical bug description"
git tag -a v0.1.1 -m "Hotfix v0.1.1"
git push origin v0.1.1
# the tag creates the GitHub release and container image, then merge back to main
git checkout main
git merge hotfix/0.1.1
git push origin main
```
