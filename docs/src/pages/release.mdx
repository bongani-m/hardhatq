# Release Process

## Versioning

HardhatQ follows [Semantic Versioning](https://semver.org/).

## Creating a Release

1. Create and push a version tag:
   ```bash
   git tag -a v0.1.0 -m "Release v0.1.0"
   git push origin v0.1.0
   ```

2. GitHub Actions creates the GitHub release and publishes the container image. The release assets are:

   - `hardhatq-darwin-arm64`
   - `hardhatq-darwin-amd64`
   - `hardhatq-linux-arm64`
   - `hardhatq-linux-amd64`

   The image is `ghcr.io/bongani-m/hardhatq` tagged with the version. A stable tag is also published as `latest`. Tags containing `-alpha`, `-beta`, or `-rc` are marked prerelease and do not move `latest`.

3. Verify the release:
   - Check that all four binaries are attached
   - Download one binary and run `./hardhatq-linux-amd64 --version`
   - Confirm the image exists at `ghcr.io/bongani-m/hardhatq:<tag>`

## Manual Build

```bash
cd src/amqp-go
VERSION="v0.1.0"

CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -ldflags="-s -w -X main.version=${VERSION}" -o hardhatq-darwin-arm64 ./cmd/amqp-server
CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build -ldflags="-s -w -X main.version=${VERSION}" -o hardhatq-darwin-amd64 ./cmd/amqp-server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w -X main.version=${VERSION}" -o hardhatq-linux-amd64 ./cmd/amqp-server
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -ldflags="-s -w -X main.version=${VERSION}" -o hardhatq-linux-arm64 ./cmd/amqp-server
```

## Hotfix Releases

1. Create a hotfix branch from the release tag:
   ```bash
   git checkout -b hotfix/0.1.1 v0.1.0
   ```

2. Make the fix, update CHANGELOG.md, commit.

3. Tag and push:
   ```bash
   git tag -a v0.1.1 -m "Hotfix v0.1.1"
   git push origin v0.1.1
   ```

4. Pushing the tag creates the GitHub release and container image.

5. Merge back to main:
   ```bash
   git checkout main
   git merge hotfix/0.1.1
   git push origin main
   ```
